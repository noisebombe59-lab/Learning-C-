Value Types (Типы-значения)
Числа (int, double), логические (bool), структуры (struct), перечисления (enum).

Где хранятся: В стеке (если объявлены локально внутри метода).

При присваивании: Данные полностью копируются в новую ячейку памяти. Изменение одной переменной никак не влияет на другую.

Поведение с null: Не могут быть null (для этого нужен Nullable / ?).

Производительность: Работают быстрее, не нагружают сборщик мусора (GC).

Шпаргалка к терминам:

Стек (Stack): Быстрая память фиксированного размера. Работает по принципу «последний пришел — первый ушел». Память очищается автоматически в момент выхода из метода.

Полная копия: Создание новой изолированной ячейки памяти с дубликатом данных. Изменение копии не меняет оригинал.

    // Пример работы Value Types
.

    int a = 5;
    int b = a; // Значение '5' полностью скопировано в новую ячейку 'b'
    b = 10;    // Изменяем 'b'
    
    Console.WriteLine(a); // Выведет 5 (переменная 'a' не изменилась)
    Console.WriteLine(b); // Выведет 10


Reference Types (Ссылочные типы)
Классы (class), интерфейсы (interface), массивы, строки (string).

Где хранятся: Сам объект — в куче. В переменной хранится только адрес (ссылка) на эту область памяти.

При присваивании: Копируется только адрес. Обе переменные начинают указывать на один и тот же объект в куче.

Поведение с null: Могут быть null (когда ссылка ведет в никуда).

Производительность: Требуют времени на выделение памяти и нагружают сборщик мусора (GC).

Шпаргалка к терминам:

Куча (Heap): Это общая память приложения, куда складываются объекты, чьи размеры не известны заранее или которые должны жить дольше, чем работает текущий метод. Объекты живут там до тех пор, пока на них есть хотя бы одна ссылка.

Копирование ссылки: Передача адреса объекта. Если изменить данные через одну переменную, изменения сразу будут видны через другую, так как объект в куче один.

Сборщик мусора (GC): Системная программа, которая периодически сканирует кучу, находит объекты без активных ссылок и удаляет их для освобождения памяти.

    // Пример работы Reference Types
.

    User user1 = new User { Name = "Илья" };
    User user2 = user1; // Скопировался только АДРЕС. Обе переменные смотрят на один объект.
    
    user2.Name = "Антон"; // Меняем имя через вторую переменную
    
    Console.WriteLine(user1.Name); // Выведет "Антон" (объект-то один и тот же)
    Console.WriteLine(user2.Name); // Выведет "Антон"

struct vs class — когда что использовать

struct — используй для:
• Маленьких неизменяемых данных (≤ 16–24 байт)
• Point, Guid, DateTime, маленькие DTO

class — используй для:
• Сущностей, сервисов, всего остального
• Когда нужно наследование или null

    Пример кода
    public readonly struct Money
    {
        public decimal Amount { get; }
        public string Currency { get; }
        public Money(decimal amount, string currency) => (Amount, Currency) = (amount, currency);
    }

Nullability (C# 8+) — обязательно включай в проекте!

    Nullable value types
    int? nullableInt = null;   // можно null
    int regularInt = 5;        // нельзя null (компилятор предупредит при присваивании null)
    
    Nullable reference types
    string? maybeNull = null;     // явно допускает null
    string notNull = "text";      // компилятор предупредит, если присвоить null

Полезные операторы для null

    user?.Profile?.Orders?.Count           // ?. — безопасный доступ (null-conditional)
    
    items?[0]?.Name                        // ?[] — безопасный индекс
    
    var count = list?.Count ?? 0;          // ?? — значение по умолчанию если null
    
    var config = settings ??= new Config(); // ??= — присвоить, если null

Важные правила

• Value types копируются полностью — изменения в копии не влияют на оригинал.
• Reference types — изменения через любую ссылку влияют на общий объект.
• string — reference type, но ведёт себя как value (immutable).
• Включай <Nullable>enable</Nullable> в .csproj — компилятор поможет избежать NullReferenceException.
• readonly struct — лучший выбор для маленьких иммутабельных данных.
