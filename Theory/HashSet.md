## HashSet<T> (Множество уникальных элементов)

Коллекция, которая хранит только уникальные элементы и обеспечивает мгновенный доступ к ним. Порядок добавления элементов внутри коллекции не сохраняется.

---

### Механика работы под капотом

* **База:** Работает на основе хеш-таблицы (как Dictionary), но хранит только ключи, без значений.
* **Поиск:** Для каждого элемента вычисляется числовой код (хеш). Программа ищет элемент сразу по этому коду, минуя последовательный перебор всей коллекции.

* **O(1) в среднем:** Время выполнения операции (добавление, поиск, удаление) фиксировано и не зависит от размера коллекции. Поиск среди 10 элементов и среди 10 000 000 займет одинаковое время.
* **Хеш-функция:** Алгоритм, который преобразует любой объект в одно число (хеш-код).
* **Коллизия:** Ситуация, когда у двух разных объектов совпали хеш-коды. Скорость операции падает с O(1) до O(n).

---

### Операции и их сложность

* **Add("value") — O(1):** Добавляет элемент. Возвращает bool (true = добавлен, false = уже был в коллекции).
* **Contains("value") — O(1):** Мгновенно проверяет наличие элемента в коллекции по его хеш-коду. Работает быстрее, чем List.Contains().
* **Remove("value") — O(1):** Находит элемент по хешу и удаляет его без сдвига остальных элементов в памяти.

### Фильтрация дубликатов

```csharp
// Быстрое удаление дубликатов из огромного списка за O(n)
List<string> rawData = new List<string> { "apple", "banana", "apple" };
HashSet<string> unique = rawData.ToHashSet(); 

// Если на выходе снова нужен список:
List<string> cleanList = rawData.ToHashSet().ToList();
Операции над множествами
C#
setA.UnionWith(setB);           // Объединение: в setA останутся все элементы из A и B
setA.IntersectWith(setB);       // Пересечение: в setA останутся только ОБЩИЕ элементы
setA.ExceptWith(setB);          // Разность: из setA удалится всё, что есть в setB
setA.SymmetricExceptWith(setB); // XOR: в setA останутся элементы, которые есть только в A или только в B

bool isSubset = setA.IsSubsetOf(setB); // true, если множество A полностью находится внутри B
Использование ссылочных типов в качестве ключей
По умолчанию для ссылочных типов (class) HashSet сравнивает ссылки на объекты (адреса в памяти), а не их внутреннее содержимое.

C#
// ПЛОХО: Объекты уникальны по ссылке, HashSet добавит оба, несмотря на одинаковые данные
class User { public string Name { get; set; } }
var badSet = new HashSet<User>();
badSet.Add(new User { Name = "Илья" });
badSet.Add(new User { Name = "Илья" }); // Добавится второй раз!

// ОТЛИЧНО: record автоматически переопределяет сравнение по значениям свойств
record User(string Name);
var goodSet = new HashSet<User>();
goodSet.Add(new User("Илья"));
goodSet.Add(new User("Илья")); // HashSet проигнорирует дубликат, вернет false
Сноски и важные правила
Работа со строками: По умолчанию строки сравниваются с учетом регистра. Для создания регистронезависимого множества обязательно передавайте компаратор в конструктор: var set = new HashSet<string>(StringComparer.OrdinalIgnoreCase);

Изменение объектов внутри множества: Никогда не изменяйте свойства объекта, если он уже добавлен в HashSet и эти свойства влияют на расчет его GetHashCode. Объект «потеряется» внутри структуры, и его невозможно будет найти или удалить.

Сравнение с аналогами: Если критически важно сохранять порядок добавления элементов, вместо HashSet используется List. Если элементы должны быть уникальными, но при этом автоматически сортироваться по возрастанию/алфавиту, используется SortedSet (работает медленнее, за O(log n)).
