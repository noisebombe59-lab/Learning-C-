      1. Что такое API и Эндпоинты
API (Application Programming Interface): «Внешняя оболочка» программы. Фронтенд (сайт или мобилка) не знает, как устроена внутренняя логика бэкенда и база данных, он общается с сервером через строго определенные «двери» — Эндпоинты.

Формула эндпоинта: URL-путь + HTTP-глагол (например: GET /api/stock).

      2. Маршрутизация и атрибут [ApiController]
Маршрутизация (Routing) — это система навигации, которая связывает URL-адрес запроса с конкретным методом (экшеном) в C#.

Атрибут [ApiController]: Твой «автопилот». Он автоматически проверяет ошибки ввода (ModelState) и определяет, откуда именно извлекать данные.

      [ApiController] // Автопилот: сам вернет 400 Bad Request, если данные — мусор
      [Route("api/stock")] // Общий базовый путь для всех методов в этом контроллере
      public class StockController : ControllerBase 
      {
          [HttpGet("{id}")] // Конкретный путь для метода: api/stock/5
          public IActionResult GetById([FromRoute] int id) 
          {
              return Ok();
          }
      }

      3. Атрибуты-источники данных ([From...])
Эти атрибуты жестко указывают системе, в какой именно части HTTP-запроса лежат нужные переменные:

[FromBody] — Данные лежат внутри тела запроса в формате JSON. Используется для создания и изменения объектов (POST, PUT).

[FromRoute] — Данные вытаскиваются прямо из URL-пути. Если URL равен api/stock/5, то [FromRoute] int id заберет цифру 5.

[FromQuery] — Данные берутся из параметров фильтрации в URL (после знака ?). Если URL равен api/stock?symbol=AAPL, атрибут вытащит значение AAPL.

      4. Результаты методов: интерфейс IActionResult
Методы контроллера возвращают не сырые объекты, а статус-коды HTTP, чтобы фронтенд точно понимал, что произошло.

✅ Успех (Статусы 2xx)
Ok(данные) (200 OK): «Всё в порядке, вот то, что ты просил». Стандарт для GET-запросов.

CreatedAtAction(...) (201 Created): «Объект успешно создан, найти его можно вот по этому адресу». Стандарт для POST-запросов.

NoContent() (204 No Content): «Я всё сделал (обновил/удалил), но данных в ответ не пришлю, так как возвращать нечего». Стандарт для DELETE и PUT.

❌ Ошибки клиента (Статусы 4xx)
BadRequest() (400 Bad Request): «Ты прислал некорректные данные (не пройдена валидация JSON)».

Unauthorized() (401 Unauthorized): «Я тебя не знаю, сначала предъяви паспорт/залогинься».

Forbid() (403 Forbidden): «Личность подтверждена, но у тебя нет прав на это действие».

NotFound() (404 Not Found): «Я искал в базе данных, но по этому ID ничего не существует».

💥 Ошибки сервера (Статусы 5xx)
Problem() (500 Internal Server Error): «Упс, у меня на сервере что-то упало (ошибка в логике C# или сбой базы данных)».

Использование CreatedAtAction на практике:
Этот метод возвращает статус 201 и добавляет в заголовки ответа (Headers) поле Location со ссылкой на новый объект, чтобы фронтенд мог сразу перенаправить туда пользователя.

      [HttpPost]
      public async Task<IActionResult> Create([FromBody] CreateStockDto dto) 
      {
          var model = dto.ToModel();
          await _context.Stocks.AddAsync(model);
          await _context.SaveChangesAsync();
          
          // Возвращаем статус 201, визитку с адресом метода GetById и готовые DTO данные
          return CreatedAtAction(nameof(GetById), new { id = model.Id }, model.ToStockDto());
      }

      5. Методы расширения (Ручной Маппинг)
Конструкция вида model.ToStockDto() — это Extension Method (метод расширения). Способ «приклеить» свой кастомный метод к уже существующему классу, чтобы держать контроллеры чистыми.

Правила создания: Класс должен быть public static, метод должен быть public static, а перед первым аргументом обязательно ставится ключевое слово this.

      public static class StockMapper 
      {
          // Теперь у любого объекта типа Stock появится метод .ToStockDto()
          public static StockDto ToStockDto(this Stock stockModel) 
          {
              return new StockDto {
                  Symbol = stockModel.Symbol,
                  Purchase = stockModel.Purchase
                  // ⚠️ Мы НЕ копируем сюда коллекцию Comments, чтобы избежать циклов в JSON!
              };
          }
      }

Как избежать зацикливания зависимостей:В зависимости от контекста запроса пользователя, убирай перекрестные ссылки в DTO:Ищем автора $\rightarrow$ Автор главный, книги второстепенные $\rightarrow$ В DTO автора у книг убирается ссылка назад на автора.Ищем книгу $\rightarrow$ Книга главная, автор второстепенный $\rightarrow$ В DTO книги у автора убирается ссылка назад на список его книг.
