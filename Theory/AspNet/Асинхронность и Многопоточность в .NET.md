    1. Базовые понятия и терминология
Thread Pool (Пул потоков): Ограниченный набор «рабочих рук» сервера, которые обрабатывают входящие запросы.

Task: Объект, представляющий собой запущенную асинхронную операцию, позволяющий отслеживать её состояние и результат.

async: Модификатор метода, который разрешает использовать ключевое слово await и заставляет компилятор превратить метод в «стейт-машину» (способную останавливаться и возобновляться).

await: Команда потоку временно покинуть метод. Поток возвращается в Thread Pool и может обрабатывать запросы других юзеров, пока выполняется внешняя операция.

    2. Типы задач: I/O-Bound против CPU-Bound
I/O-Bound задача (Ввод/Вывод)
Суть: Скорость упирается исключительно во внешний мир (база данных, сеть, жесткий диск).

Поведение: Программа отправляет запрос наружу и ждет. Процессор при этом ничем не занят (0% нагрузки).

Примеры: Запрос к SQL-серверу, чтение JSON-файла с диска, скачивание картинки по API.

Решение (async/await): Поток дает команду внешнему миру и возвращается в пул. Когда данные прилетают, любой свободный поток из пула подхватывает метод и продолжает его с места остановки.

CPU-Bound задача (Вычисления)
Суть: Скорость упирается в вычислительную мощность твоего процессора. Ожидания нет, программа считает всё сама внутри оперативной памяти (RAM).

Поведение: Поток непрерывно работает на 100%, выполняя тяжелые математические или логические операции.

Примеры: Циклы по огромным массивам, маппинг объектов в памяти, хэширование паролей, архивация файлов.

Решение (Task.Run): Чтобы тяжелые вычисления не заблокировали основной поток (и интерфейс/сервер не завис), задачу вручную переносят на фоновый поток через Task.Run().

    3. Практическая визуализация в коде (Квинтэссенция)
.

    C#
    [HttpGet("{id}")]
    public async Task<IActionResult> GetStockById([FromRoute] int id) 
    {
        // 1. В метод заходит поток из Thread Pool.
    
        // 2. I/O-Bound операция (Обращение к базе данных).
        // Доходим до await. Поток дает команду SQL-серверу "Ищи!" и ТУТ ЖЕ уходит в пул.
        // Пока база работает (например, 200мс), этот поток обслуживает других юзеров.
        var stock = await _context.Stocks.FirstOrDefaultAsync(x => x.Id == id);
    
        // 3. База ответила. Любой свободный поток из пула возвращается в метод.
        if (stock == null) 
        {
            return NotFound();
        }
    
        // 4. CPU-Bound операция (Работа в памяти).
        // Данные уже в RAM. Процессор мгновенно перекладывает их через маппер. 
        // await тут НЕ НУЖЕН — это быстрая синхронная работа самого CPU.
        var dto = stock.ToStockDto(); 
    
        return Ok(dto);
    }
💡 Главный итог
Используй async/await для I/O-Bound задач (база, сеть), чтобы не транжирить Thread Pool на бесполезное ожидание, и оставляй CPU-Bound задачи (логика в памяти) синхронными, так как процессору нужно выполнять эту работу здесь и сейчас.
