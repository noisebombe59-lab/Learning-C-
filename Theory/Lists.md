List<T> (Динамический массив)

Обертка над обычным фиксированным массивом T[]. Когда массив заполняется, List<T> автоматически создает в куче новый массив большего размера и копирует данные туда.

Механика работы под капотом

Count — сколько элементов реально лежит в списке на данный момент.

Capacity — размер внутреннего массива. По умолчанию он равен 4, а при заполнении удваивается (4 → 8 → 16 → 32...).

$O(1)$ — мгновенная операция. Время выполнения не зависит от количества элементов (например, взять элемент по индексу).

$O(n)$ — медленная операция. Время выполнения зависит от количества элементов $n$, так как программе приходится перебирать весь список или сдвигать элементы в памяти.

Операции и их сложность (Критично для собеседования)

Доступ / изменение по индексу (list[0]) — $O(1)$: Работает мгновенно, так как это прямое обращение к ячейке памяти.

Добавление в конец (Add) — $O(1)$ в среднем: Просто вставка в следующую свободную ячейку внутреннего массива.

Исключение: Если Count == Capacity, то операция становится $O(n)$, потому что создается новый массив и в него копируются все старые элементы.

Вставка / удаление в середине (Insert, Remove) — $O(n)$: Очень дорогая операция. Программе приходится сдвигать в памяти все элементы, стоящие после измененного места, на один шаг влево или вправо.

// ПЛОХО: если добавить 100 000 элементов, массив внутри пересоздастся и скопируется около 15 раз
var list = new List<int>(); 

// ОТЛИЧНО: внутренний массив сразу создается нужного размера. Пересозданий и копирований — 0
var optimizedList = new List<int>(capacity: 100_000);


Правила удаления

Критическая ошибка (Приведет к падению программы с InvalidOperationException):

// ОШИБКА! Нельзя удалять элементы внутри foreach
foreach (var item in fruits)
{
    if (item == "banana") fruits.Remove(item); 
}


Почему падает: foreach под капотом использует специальный объект-итератор, который строго следит за неизменностью коллекции во время обхода. Если удалить элемент «на лету», итератор ломается.

Правильный подход:

// Работает быстро, безопасно, сдвигает элементы в памяти всего один раз за всю операцию
fruits.RemoveAll(f => f == "banana");


Шпаргалка по методам

fruits.Contains("apple") — Поиск элемента. Работает за $O(n)$, так как последовательно перебирает список с самого начала.

fruits.Find(x => x.Length > 5) — Возвращает первый совпавший элемент или null.

fruits.TrimExcess() — Принудительно уменьшает Capacity до размера Count. Используется для экономии памяти, если из огромного списка удалили большую часть элементов.

Сноски и важные правила

Выбор между List<T> и массивом: Массив используется, когда размер данных жестко известен заранее и гарантированно не изменится (например, количество месяцев в году или дней в неделе). Во всех остальных случаях применяется List<T>, так как он берет управление динамической памятью на себя.

Производительность: Обычный массив (T[]) работает быстрее. У него отсутствуют накладные расходы на логику обертки, ручную проверку границ коллекции и затраты времени на автоматическое удвоение емкости при заполнении.
