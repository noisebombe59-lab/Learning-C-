List<T> (Динамический массив)
Обертка над обычным фиксированным массивом T[]. Когда массив заполняется, List<T> автоматически создает в куче новый массив большего размера и копирует данные туда.

Механика работы под капотом
Base: Обертка над обычным фиксированным массивом T[].

Count — сколько элементов реально лежит в списке на данный момент.

Capacity — размер внутреннего массива. По умолчанию он равен 4, а при заполнении удваивается (4 → 8 → 16 → 32...).

O(1) — мгновенная операция. Время выполнения не зависит от количества элементов (например, взять элемент по индексу).

O(n) — медленная операция. Время выполнения зависит от количества элементов n, так как программе приходится перебирать весь список или сдвигать элементы в памяти.

Операции и их сложность (Критично для собеседования)
Доступ / изменение по индексу (list[0]) — O(1): Работает мгновенно, так как это прямое обращение к ячейке памяти.

Добавление в конец (Add) — O(1) в среднем: Просто вставка в следующую свободную ячейку внутреннего массива.

Исключение: Если Count == Capacity, то операция становится O(n), потому что создается новый массив и в него копируются все старые элементы.

Вставка / удаление в середине (Insert, Remove) — O(n): Очень дорогая операция. Программе приходится сдвигать в памяти все элементы, стоящие после измененного места, на один шаг влево или вправо.

C#
// ПЛОХО: если добавить 100 000 элементов, массив внутри пересоздастся и скопируется около 15 раз
var list = new List<int>(); 

// ОТЛИЧНО: внутренний массив сразу создается нужного размера. Пересозданий и копирования — 0
var optimizedList = new List<int>(capacity: 100_000);
Правила удаления
Критическая ошибка (Приведет к падению программы с InvalidOperationException):

C#
// ОШИБКА! Нельзя удалять элементы внутри foreach
foreach (var item in fruits)
{
    if (item == "banana") fruits.Remove(item); 
}
Почему падает: foreach под капотом использует специальный объект-итератор, который строго следит за неизменностью коллекции во время обхода. Если удалить элемент «на лету», итератор ломается.

Правильный подход:

C#
// Работает быстро, безопасно, сдвигает элементы в памяти всего один раз за всю операцию
fruits.RemoveAll(f => f == "banana");
Шпаргалка по методам
fruits.Contains("apple") — Поиск элемента. Работает за O(n), так как последовательно перебирает список с самого начала.

fruits.Find(x => x.Length > 5) — Возвращает первый совпавший элемент или null.

fruits.TrimExcess() — Принудительно уменьшает Capacity до размера Count. Используется для экономии памяти, если из огромного списка удалили большую часть элементов.

Сноски и важные правила
Выбор между List<T> и массивом: Массив используется, когда размер данных жестко известен заранее и гарантированно не изменится (например, количество месяцев в году или дней в неделе). Во всех остальных случаях применяется List<T>, так как он берет управление динамической памятью на себя.

Производительность: Обычный массив (T[]) работает быстрее. У него отсутствуют накладные расходы на логику обертки, ручную проверку границ коллекции и затраты времени на автоматическое удвоение емкости при заполнении.

Strings и StringBuilder
string — это неизменяемый текст (каждое изменение создает новый объект), а StringBuilder — это динамический буфер, который редактирует текст внутри себя без создания лишнего мусора в памяти.

String (Строка)
Ссылка на объект в куче, но благодаря своей неизменяемости (immutable) ведет себя предсказуемо.

Каждое изменение строки (+, Replace, ToLower и др.) оставляет старый объект в памяти нетронутым и создает в куче абсолютно новую строку.

C#
string a = "hello";
a += " world"; // В куче создалась третья строка "hello world". 
               // Строки "hello" и " world" остались лежать в памяти как мусор.
Шпаргалка к терминам:

Иммутабельность (Immutable): Запрет на изменение объекта после его создания. Нельзя заменить отдельный символ внутри существующей строки, можно только пересоздать строку целиком.

Потокобезопасность строк: Поскольку строку физически невозможно изменить после создания, несколько потоков выполнения могут одновременно читать её, не боясь, что другой поток перезапишет данные в этот же момент.

StringBuilder
Изменяемый (mutable) класс-помощник для эффективной сборки и редактирования текста.

Как работает: Выделяет в куче один массив символов (буфер) и при операциях (Append, Insert) заполняет именно его. Сам объект в памяти при этом остается один и тот же.

C#
var sb = new StringBuilder();
sb.Append("hello");
sb.Append(" world"); // Данные просто дописались в тот же самый массив в памяти.
Шпаргалка к терминам:

Аллокация: Выделение нового куска оперативной памяти в куче под объект. Обычная строка делает аллокацию при каждой склейке, в то время как StringBuilder — только тогда, когда его внутренний массив полностью забивается символами.

Начальная емкость (Capacity): Размер внутреннего массива символов. Если заранее задать new StringBuilder(10_000), то массив сразу займет нужное место, и программа не будет тратить время на его расширение и копирование данных в процессе работы.

Когда что использовать
Используй string:
Для 1–5 простых склеек (компилятор сам оптимизирует их через string.Concat).

Для хранения констант, путей, URL-адресов, токенов.

Когда критически важна иммутабельность и гарантированная потокобезопасность данных.

Используй StringBuilder:
СТРОГО в любых циклах, где идет динамическая сборка или склейка текста.

Для генерации больших объемов данных (логи, HTML-разметка, CSV-файлы).

Когда над одной строкой выполняется больше 10 последовательных манипуляций.

Шпаргалка по методам для собеседования
Эффективные методы string:
string.IsNullOrWhiteSpace(str) — лучший способ проверки. Возвращает true, если строка пустая, равна null или состоит только из невидимых пробелов.

string.Join(", ", array) — быстро собирает массив в одну строку через разделитель (под капотом оптимизирован и сам использует StringBuilder).

str.Split(';') — режет строку на массив подстрок по указанному символу.

Эффективные методы StringBuilder:
sb.AppendLine("текст") — добавляет текст и автоматически переносит строку (\r\n).

sb.Clear() или sb.Length = 0 — мгновенно обнуляет буфер для повторного использования, помогая избежать создания нового объекта StringBuilder.

sb.ToString() — вызывается строго один раз в самом конце, когда текст полностью собран.

Паттерн «Плохо против Хорошо»
Критическая ошибка (создаст тысячи временных объектов и забьет кучу мусором):

C#
string log = "";
for (int i = 0; i < 10_000; i++)
{
    log += $"действие {i}\n"; // Худший код для памяти: создаст 10 000 временных строк в куче
}
Профессиональный подход (одна аллокация, ноль нагрузки на сборщик мусора GC):

C#
var sb = new StringBuilder(1_000_000); // Сразу задали Capacity с запасом
for (int i = 0; i < 10_000; i++)
{
    sb.Append("действие ").Append(i).AppendLine(); // Сборка внутри одного буфера
}
string finalLog = sb.ToString(); // Вызов только один раз в конце
